# 🏛 rightcol — 企业认知框架

**一套帮你持续回答「这家公司值不值得拥有、现在这个价格合不合理」的认知工具**，
而不是财务指标计算器。自下而上看**微观**（企业财报）；姊妹项目 **macroscope**
（本地目录名 `../risk_monitor`）自上而下看**宏观**。

> 项目宗旨一句话：**用合理的价格，买好的公司。**
>
> 核心读法见 **[`FRAMEWORK.md`](FRAMEWORK.md)**：**三个闸门**（能力圈 → 好生意 → 好价格）·
> 读财报的 **5 个主问题** · 看每个数字的 **4 个问题** · **ROIC × 增长象限**。
> 参考巴菲特与段永平的方法论；引用均经对抗性核实，段永平的话逐条标注了原始日期。

## 两个项目怎么拼成完整的图

它们不是并列关系，是**同一个式子的两端**：

```
                    ∞     现金流_t
    价值  =        Σ    ──────────────
                   t=1    (1 + r)^t
                          ╰────┬────╯
        ╰──────┬──────╯        │
               │               │
          rightcol         macroscope
        （分子：这家公司      （分母：无风险利率
          能赚多少、能赚         + 风险溢价，由增长/
          多久、多确定）         通胀/政策/金融条件决定）
```

一家公司的自由现金流收益率 5%，在 10 年期美债 1% 时是慷慨的，在美债 5% 时
毫无吸引力 —— **公司一个字没变，价值判断却反转了**。所以「合理的价格」
从来不是绝对数，它是相对无风险利率的。两边必须同时看。

## 架构 —— 为什么分成两层

```
┌─────────────────────────────────────────────────────────┐
│  确定性数据层（纯 Python · 零密钥 · 零 API 成本）          │
│  SEC EDGAR 官方 XBRL → 口径归一 → 指标计算 → 数据包        │
│  职责：把数字算对。不做任何判断。                          │
└────────────────────────┬────────────────────────────────┘
                         ↓  data/<TICKER>.md
┌─────────────────────────────────────────────────────────┐
│  LLM 精读层（Claude Code skill · 走你的订阅 · 手动触发）   │
│  读 10-K 原文 → 按三闸门判断 → 沉淀公司档案                │
│  职责：回答「所以呢」。数字之外的东西只能这样拿到。          │
└─────────────────────────────────────────────────────────┘
```

**为什么必须分层**：数字算错了，再漂亮的叙事都是有害的；而数字本身
永远不会告诉你管理层今年悄悄改了口径。两件事必须由两种东西来做。

**为什么 LLM 层不写在 Python 里**：精读走 Claude Code 订阅，
本项目运行时**零 API 成本**，也因此刻意不依赖 `anthropic` SDK。

## 第一天该做什么

**不要先跑脚本。** 这个项目的主产品是方法论，代码只是它的自动化。

1. **读 [`FRAMEWORK.md`](FRAMEWORK.md) 的 §〇 ~ §3**（约 20 分钟）。
   这部分**不需要任何数据** —— 三个闸门、读财报的 5 个主问题、看每个数字的 4 个问题。
   读完你就已经解决了"看财报不知道在看什么"这个问题的大半。
2. **打开范例档案 [`companies/COST.md`](companies/COST.md)**，看成品长什么样。
   注意它的结论是「**生意 A 级，但价格不合理**」—— 好公司 ≠ 好投资，
   这正是三个闸门要分开走的原因。
3. **挑一家你天天在用其产品的公司**跑一遍（不是你听说过的热门股 ——
   **你使用的产品就是能力圈的天然入口**，段永平买苹果走的正是这条路）。
4. **只写闸门 0。** 写不出"这门生意的钱是怎么赚的"，就停在那里。
   **这是一个有效结论，不是失败** —— 它替你省下了后面所有的功夫和亏损。

## 快速开始

```bash
pip install -r requirements.txt

# 改成你自己的邮箱（SEC 要求 User-Agent 带可联系信息，否则 403）
export RIGHTCOL_UA="your-name your@email.com"
```

### 分析一家公司

```bash
# 1) 确定性数据包 —— 闸门 0 与闸门 1 的数字底座
python bin/dossier.py AAPL --years 10 --filings -o data/

# 2) 闸门 2 —— 逆向 DCF：当前价格在假设什么
#    价格手动输入（EDGAR 不含股价，且这会提醒你「价格是你选的输入」）
python bin/value.py AAPL --price 255

# 3) 在 Claude Code 里精读并沉淀档案（走订阅）
/dossier AAPL
```

### 分析一个行业

```bash
python bin/sector.py --group semis_fabless -o data/   # 横切数据 → data/sector_<组名>.md
python bin/sector.py COST WMT TGT BJ DG              # 或直接给 ticker
# ⚠️ 直接给 ticker 时，你要自己保证这组公司「赚钱方式可比」——
#    苹果(硬件,毛利47%)和微软(软件,毛利70%)放一起比毛利率毫无意义，见 FRAMEWORK §5.5

# 在 Claude Code 里做行业判断
/sector semis_fabless
```

## 数据包里有什么

| 节 | 回答 §2 的哪个主问题 | 关键指标 |
|---|---|---|
| 一 · 盈利能力与资本回报 | 赚不赚钱 | 毛利率 / 营业利润率 / **ROIC** / 增量 ROIC |
| 二 · 杜邦拆解 | 靠什么赚 | 净利率 × 周转率 × 权益乘数 |
| 三 · 现金质量 | 赚的是不是真钱 | OCF/净利 / FCF / **FCF(扣SBC)** / 应计比率 |
| 四 · 现金转换周期 | 产业链话语权 | DSO / DIO / DPO / **CCC** |
| 五 · 资本配置 | 赚的钱归谁 | **回购/SBC** / **摊薄股数与净稀释率** / SBC÷毛利 / 分红 |
| 六 · 财务健康 | 会不会突然死 | 有息负债（含租赁）/ 净负债÷FCF / 商誉÷权益 |
| 七 · 口径留痕 | 跨公司能不能比 | 各科目实际命中的 us-gaap 标签 |

每一节都附「**怎么读**」——阈值、经验带、以及**该阈值在什么情况下失效**。

## ⚠️ 定位 —— 这是什么，不是什么

**这不是选股器，不给买卖信号。** 它也**不做全市场量化筛选**——按低 PE 筛出来的
大概率是价值陷阱，且那等于把三个闸门的顺序反过来走（见 FRAMEWORK.md §8.5.A）。
它产出的是**判断依据与可证伪的命题**，
最终判断由你做出。所有措辞都是"这个价格隐含了什么假设"，**绝不**用"买/卖"。

它也**不是**一个能替你省掉思考的东西。段永平的原话：

> 「为什么说『好的生意模式、好的企业文化、好的管理团队、好价钱』也不是可以买的
> 『充分条件』？因为这样的公司也可能犯致命的错误，只是具备这种条件的公司犯致命
> 错误的概率**比没有这种条件的公司**低很多，康复能力强很多，所以投资这种公司
> 成功的概率高很多而已。」

框架是**概率放大器**，不是判定器。

### 什么时候这套框架不适用

银行/保险（没有毛利、存货、资本开支，杠杆是业务本身）、自由现金流为负的
公司（DCF 无解）、周期股顶部（PE 最低时最危险）、重组分拆中的公司。
详见 [`FRAMEWORK.md` §10](FRAMEWORK.md#十什么时候这套框架不适用诚实边界)。

## 数据的诚实声明

全部数据来自 SEC EDGAR 官方 XBRL（申报原始口径，未经任何第三方调整）。
以下限制**实测确认**，不隐瞒：

- **XBRL 只到约 2009 年**（强制申报自 2009 年分阶段推行）——百年老店也没有百年数据。
- **标签会变、会缺**：苹果的营收标签在 ASC 606 后换过；英伟达 FY2019–21
  的资本开支在 XBRL 里**根本没有被标注**。缺失一律显示 `—`，**绝不以 0 填充**。
- **主体重组会换 CIK**：2026 年 7 月 ExxonMobil 完成控股重组，SEC 的 ticker
  映射立刻指向 XBRL 历史为空的新壳；本项目会自动回溯前身主体。
- **拆股不做追溯调整**：股数与 EPS 是各次报送的原始值，跨拆股年份不可比。
- **拿不到分部数据**：companyfacts 只聚合无维度事实，分部拆分需回原文。
- **ROIC 略偏乐观**：超额现金未扣除经营所需最低现金。
- **经营租赁做了近似**：按 5% 隐含利率还原租金中的利息部分。

> 数据中断必须长得像数据中断 —— 本项目**绝不**把缺失伪装成 0 或"正常"。

"广为流传"而非直接引用。
